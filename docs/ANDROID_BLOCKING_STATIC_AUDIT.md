# Android blocking: static completion audit

This audit inspects the supplied 6.0.3 APK's retained Java and raw smali. **No behavioral tests were run.** It closes the explicit paths described below, not protected dispatch, Android engine timing, or effective device state. The [current register](ANDROID_BLOCKING_GAPS.md#current-gap-register) distinguishes those limits.

The scan covers 46,271 smali files and 250,119 method declarations. [Inventory](../results/android-blocking-static-audit/inventory.json) records exact direct callers/writers, selected method ranges, source hashes and a lexical rule census. [Evidence index](../results/android-blocking-static-evidence-index.json) selects the unchanged [full Java/smali snapshots](../code-evidence/android/ad-blocking/static-audit/README.md) and complete-method excerpts. Run `python3 scripts/audit_android_blocking_static.py`, then `python3 scripts/organize_code_evidence.py` to regenerate from the complete archive. Then run `python3 scripts/verify_android_blocking_static.py` for byte/hash, method-range, rule-inventory and local-link integrity checks. These scripts inspect text and copy evidence; they do not execute app logic or simulate a matching engine.

Citations use **physical file lines**, not smali `.line` annotations. Unless qualified, `X.smali` means `working/apktool/smali_classes6/X.smali`; the evidence index supplies the complete path. `smali/` and `classes7/` prefixes below identify different dex directories. Java is a readability aid; raw instructions control when the decompiler disagrees. The following short-name exceptions resolve unqualified citations: `smali/{b2c,c2a,d9,dp9,g9,gy0,ie2,je2,jzc,la,mrb,n74,nt4,pv7,q0,r0,rh8,rx8,s0,sw,tw,ub,uqd,uw,vh8,xv7,ygc,z1a}.smali`; `smali_classes2/{ol4,tu5}.smali`; `smali_classes5/{aw3,cu1,ita,rm9,zn0}.smali`; `smali_classes7/{bdd,dl9,hra,j6b,n22,p5b,pw6,q6b,rp7,vj5,yv0}.smali`.

## B01 — Redirect expressions and helpers

The [factory](../code-evidence/android/ad-blocking/excerpts/static-B01-factory.smali.txt), `s92.h:755–2116`, recognizes **29 operator names**, after trimming the operator and lowercasing with `Locale.ENGLISH`. The field name remains literal. `classes7/hra.g:1324–1346` is a Map lookup. The expression value is trimmed by `kd` before alternative parsing; elements are trimmed, not case-normalized there.

| Operators (names accepted case-insensitively) | Predicate and implementation |
|---|---|
| `contains`, `containsIgnoreCase` | Substring search; `z1a` selectors 27/28 (`smali/z1a.invoke:103–222`). Ignore-case explicitly lowercases both strings with ROOT. |
| `endsWith`, `startsWith` | Case-sensitive suffix/prefix via `classes7/q6b.u0/E0` with ignoreCase=false; `z1a` default branch and `jra` selector 9. |
| `equals`, `equalsIgnoreCase` | Object/String equality; ignore-case lowercases both with ENGLISH (`jra` selectors 0/1, 1474–1534 for 1). This is not a call to Unicode `String.equalsIgnoreCase`. |
| `notContains`, `notEquals`, `notEqualsIgnoreCase` | Negative `rra` branch wrapping the corresponding positive predicate (`jra` selectors 2/3/4). They mean **none of the alternatives match**, not “at least one alternative differs.” |
| `matchesRegex`, `notMatchesRegex` | Positive/negative `lra.b:29–342`; `ora.<init>:20–139` compiles every alternative through `classes7/dl9`. Java `Pattern.compile(String)` and `Matcher.find`, no implicit flags or full-string anchoring. Inline Java regex flags still apply. |
| `setContainsAll`, `setContainsAllIgnoreCase` | Actual Set contains every configured element; `jra` selectors 5/6 (1213–1332). |
| `setContainsAny`, `setContainsAnyIgnoreCase` | Nonempty intersection; `jra` selectors 7/8. |
| `setContainsAtLeast50Percent`, `setContainsAtLeast60Percent`, `setContainsAtLeast70Percent`, `setContainsAtLeast80Percent`, `setContainsAtLeast90Percent`, and each corresponding `IgnoreCase` suffix | `pra` builds `qra`; floor of `percent/100 * configuredSet.size`, then requires intersection nonempty, threshold > 0 and intersection size >= threshold (`qra.invoke:38–309`). The denominator is **configured**, not actual, set size. |
| `isNull`, `isNotNull`, `isMimeHls`, `isSandboxUrl` | `kra.b:54–139` passes a String or null to `smali/c2a` selectors 24/23/22/25. Non-String values are converted to null for these predicates. |

[String evaluation](../code-evidence/android/ad-blocking/excerpts/static-B01-string.smali.txt), `rra.b:124–457`: positive predicates require a String and any matching alternative. Missing/null/non-String values fail positive predicates but satisfy the negative branch. A genuinely empty alternative collection makes positive false and negative true. `lra` has the analogous positive/negative behavior. `ora.b:204–305` requires a Set; missing/null/non-Set values fail all Set predicates, including ContainsAll. For an actual Set and genuinely empty configured Set, ContainsAll is true and ContainsAny is false.

**Empty text is different from an empty collection.** `kd` does not drop empty comma-separated alternatives. Its Kotlin literal split helper `classes7/j6b.k1` retains empty elements at limit 0, unlike Java's default `String.split`. Under the intended bracket delimiter, `[]` therefore yields one empty-string alternative. Empty scalar alternatives can match any String under contains/prefix/suffix, only empty String under equality, and anywhere under empty regex. `::` and `;;` are literal delimiters with no quoting or escaping grammar; commas inside bracketed regex alternatives also split. A backslash is passed to Java regex, not interpreted as a JSON escape by this grammar.

Ignore-case Set helpers `s92.f:487–588` stringify each element (`null` becomes `"null"`), lowercase with ROOT and deduplicate. Ordinary Set operations preserve Java element equality. Configured alternatives are converted to a Set before evaluation; the ignore-case percentage threshold is computed **before** lowercasing, so differently cased alternatives can collapse afterward while the threshold still reflects the larger raw Set. A floor of zero never matches, even when an intersection exists. These are static consequences, not executed examples.

`isMimeHls` calls `uc7.m:1827–1987`: null is false; ENGLISH lowercase then substring checks for `application/x-mpegurl`, `application/vnd.apple.mpegurl`, `audio/x-mpegurl`, `m3u8`, `application/octet-stream-m3u8`, `text/x-mpegurl`, `video/m3u8`, `video/vnd.mpegurl`. This is not exact MIME parsing. `isSandboxUrl` calls `classes7/yv0.C:1009–1067` → `s92.o:2118–2265` → `tdc.a:72–239` → `sdc.a:226–487`: configurable JSON matcher, fallback on unavailable/blank config or JSON-construction exception, OR across prefix/contains/suffix/regex lists, ENGLISH lowercase of candidate input **and every configured list entry** (`sdc.b:45–222`). `tdc.b:241–489` reads only present keys as JSON arrays with getString; no separate type validation or trimming is added. The JSON regex helper (`smali/mrb:2518–2569`) compiles the lowercased pattern and uses find on every evaluation; invalid regex can throw at evaluation rather than trigger the JSON-construction fallback. Its protected contains-key remains unresolved above; a malformed fallback can still propagate.

[URL context](../code-evidence/android/ad-blocking/excerpts/static-B01-context.smali.txt), `ld.a:135–365`, stores original `url`, Android `Uri.getHost()`, `getPath()`, and `getQueryParameterNames()` as a **Set of names**, not values. The `Objects.toString` return is discarded. There is no additional lowercase, IDN conversion, percent-decoding, plus conversion or URL canonicalizer in `ld`; decoding/opaque-URI behavior is delegated to Android Uri. It has no local catch around Uri or matcher failures. Outer callers have their own failure handling; do not describe every malformed URL as an ordinary nonmatch. `cra.a`/`era` combine retained clauses ALL/AND, while `ld.a` searches separate rules first-match/OR.

**Status:** explicit factory/operator/helper trace complete; protected delimiter and sandbox-key initialization remain static gaps. Android URI/regex compatibility and effective rule construction remain unverified.

## B02 — Supplied-rule census and error construction

The lexical census in the [inventory](../results/android-blocking-static-audit/inventory.json) hashes each input and records every active physical line. It does not execute the APK parser.

| Input | Active rows | Operators, counted per clause |
|---|---:|---|
| Packaged `ad_redirect_block_add.txt` | 5 | matchesRegex 1; contains 3; setContainsAllIgnoreCase 4; setContainsAnyIgnoreCase 1 |
| Packaged `ad_redirect_block_remove.txt` | 0 | None |
| Retained remote `developer-redirects.txt` | 2 | contains 1; setContainsAllIgnoreCase 2 |

The remote snapshot was retrieved **2026-10-16**, not during this audit. Both remote rules duplicate packaged rules textually; seven physical rows represent five distinct active rule strings. Every supplied clause has three `::` parts, every named operator is recognized, bracketed alternatives are nonempty text, and there are no percent operators or single-part shorthand inside multi-expression rules. Thus the supplied text does **not** exercise the three requested edge families (subject to the protected delimiter caveat). This says nothing about a phone's later downloaded rules.

`kd.invokeSuspend:2293–2827` establishes the error paths: wrong arity logs `Invalid rule definition` → null clause; unmatched alternative boundaries log `Invalid alternatives for expression` → null; factory exceptions (including invalid regex/unknown operator) log `Could not parse expression` → null. Single-part shorthand constructs a URL regex from **dra.c, the entire original line** (2712–2731), even inside a `;;` rule; its exceptions log `Invalid RegEx`. Null clauses are dropped (2775–2781), a surviving nonempty list becomes a `cra(ALL)` (2794–2827), and a rule with no survivors is omitted. This can weaken an intended conjunction. These catches do not enclose the protected suffix access/comparison at 2459–2464.

**Status:** static trace and supplied-text census complete; edge behavior is source-demonstrated, not a reproduced defect. Protected initialization still prevents certifying native construction of even these apparently well-formed rules.

## B04 — Loading, refresh and overlap

[Enqueue](../code-evidence/android/ad-blocking/excerpts/static-B04-enqueue.smali.txt), `a9.b:267–538`, starts a separate `z8` cancellation coroutine, creates UUID/tagged **one-off** WorkManager `v60(AdBlockLoadWorker)`, serializes appInstance/uuid/trigger/forced, and calls ordinary `o4d.b` enqueue. `a9.c:540–547` sets forced=true and returns progress flow. Explicit callers: `smali/r0` CONFIG_CHANGE (5202–5210) and `kv9` RESET (5647–5668). `db` also defines BROWSER, but no explicit caller passes that enum to enqueue. Only this enqueue construction references the worker class in the retained direct scheduling code; no periodic WorkRequest/timer was found for it. A preference labelled “update” is not proof of a schedule.

`va.c` snapshots default/custom toggles plus database row count/max(updated) for each custom table (`ib2.a`), not a content hash or 1Hosts/remote-config snapshot. `va.b:640–780` compares before/after; change launches `smali/r0` selector 8 to force enqueue. `t8:10422` calls this when the list-management dialog returns. Add/edit/delete/enable/reorder update DB state (`ba`, `da`), so this comparison detects their ordinary timestamp/count changes **on that return path**, not through an always-running table subscriber. `smali/r0:5336` captures a configuration snapshot; its dependent validation/UI branches are preserved in full.

Reset in the blocking fragment explicitly forces a rebuild (`kv9`). Advanced settings reset (`hia.onClick:108–273`) clears cast/default/app/utils preferences then finishes the activity; it does not call `a9` or `kd` in that visible body. Generic restore (`be2`, `wz8.d`) does not call them either. Subsequent protected startup can change the outcome: **immediate refresh after restore/global reset, initial load and browser-start scheduling remain unresolved**.

Cancellation is best-effort coordination: `z8.invokeSuspend:~4390–4879` selects other same-app-instance/other-UUID TRIGGERED or LOADING rows, requests WorkManager cancellation by their tags and marks them CANCELED through `fc.h`. It is launched separately before enqueue; enqueue does not await completion, use unique-work replacement, or hold a rebuild-wide mutex. Workers may overlap before cancellation takes effect; a later activation can win. `AtomicLong` in the worker labels/counts executions; it is not mutual exclusion.

Cache selection is independent of `forced`: `fn9.a:97–242` uses category/source ID and deletes files older than 604,800,000 ms on access. `qb2` uses custom category and `mc.a:422–463` constructs `custom_blocklist_<id>_<updated>`; editing timestamps selects a new cache key. `jr2` uses stable default source IDs, `nm9` separate `ad_redirect_block` category; URL changes do not themselves become the filename. `mc.b:1004–1067` reads `pref_update_adblock_list_key` (default true) to include the 1Hosts source. The developer ADD_REMOVE remote source is constructed afterward independently. Force does not force every source onto the network.

Redirect loading is `kd` **selector 0**, `invokeSuspend:884–2884`: parallel source jobs → await → merge/parse → one assignment `ld.c` at 2880; there is no assignment to null at start. A thrown/aborted load can therefore leave the prior map, whereas handled source failures can publish a reduced map. No explicit external constructor call sets `kd.r=0`; other apparent `kd` calls select unrelated synthetic branches. `ld.<clinit>` creates sources but does not launch selector 0. Its startup/reload trigger, job retention/cancellation and overlap cannot be finished through the visible graph. There is no proved periodic redirect refresh.

**Status:** visible scheduling/cache/edit/reset/restore paths traced; protected initial/browser-start and redirect reload callers remain static gaps. Actual order, cancellation and freshness remain runtime pending.

## B05 — Popup lifecycle and cleanup callers

[Creation](../code-evidence/android/ad-blocking/excerpts/static-B05-create.smali.txt), `sg1.onCreateWindow:4388–4698`, handles the real-gesture argument `p3`:

1. Without a gesture, the “alert without gesture” preference defaults false (4416–4471); that branch sends the transport message with no child and returns true. A real gesture proceeds to child creation.
2. Creates a WebView. With popup behavior disabled, sets the transport and posts `smali/gy0` selector 3 (1739–1847), which calls WebBrowser.n0 with first-start classification already marked handled; with it enabled (default true), constructs temporary `wzc(d=true)`, copies UA, assigns transport, sends message (4486–4693). It does not deny click-triggered window creation at entry.
3. `wzc.<init>:111–900` enables JS, JS automatic windows, multiple windows, DOM storage and installs `sg1`/`uwc`; temporary children therefore have the same nested-window entry point. No explicit popup-depth limit appears there.
4. `uwc.onPageStarted:5159–5185` classifies only `d && !p`, then sets p=true **before** URL parsing. Lowercases URL with ROOT, extracts host, checks host database (5214–5265). Unparseable URL is caught locally, leaves ad=false and the display value as URL. Ad alert preference selects notification or posted destruction; non-ad persisted prefix exception promotes automatically, otherwise notification (5300–5541). Ad classification is checked before the prefix branch.

Notification `jm9.invoke` default branch (112–361) creates Snackbar with Open action (`jp8` selector 21 → promotion `t9` selector 10) and `fu8` selector 2 dismissal callback. `fu8.a:65–87` invokes disposal for every dismissal reason **except 1 (action)**; timeout, swipe, manual and consecutive/replacement dismissal use that same path. Snackbar framework reason values, not arbitrary app replacement bookkeeping, determine the branch. `y6a` selector 24 posts `psc` selector 4 (196–225), which rechecks tab membership before destruction (`psc.run:952–1055`). A promoted WebView already in `hy0.f()` survives that callback.

There is also an **app-owned notification queue**, not just Material replacement: `smali/xv7.F0:1154–1199` launches `sv8` selector 12 (2257–2386), assigns an increasing ID and queues the Snackbar in global `lta.c`. `lta.b:173–451` locks `lta.d`, polls one, attaches `kta` and calls ita.m; kta.a (29–60) unlocks on dismissal, allowing a waiting queued notification to proceed. `classes5/ita.m:555–859` uses Material manager replacement reason 4; the Open listener invokes promotion **before** requesting reason-1 dismissal (`e0:109–122`). `classes5/zn0.d:933–983` invokes callbacks in reverse registration order: lta's later-added kta unlock precedes fu8's posted disposal, and that disposal still rechecks promotion membership.

**Cleanup boundary found:** `uwc.n:4020–4024` clears the global pending Snackbar queue without invoking its entries' fu8 callbacks or E0. Its direct callers are q:7528, onPageStarted:5707 and WebBrowser.T0:6362. Thus visible dismissal of a shown notification and removal of a still-queued notification are different paths. No explicit per-entry child disposal is shown for that queue clear; whether a particular popup becomes queued/cleared, remains active, or is reclaimed needs runtime evidence. Enqueue itself is launched asynchronously, so source order is not a measured UI/callback timeline.

Promotion `t9.invoke:683–782` adds the **same wzc/WebView** to `hy0`, selects it, then optionally offers persistent allowance. It does not reconstruct the page or explicitly stop loading. The `d` flag is not cleared there, but p=true prevents another first-start classification. `WebBrowser.n0:12643–12680` also assigns p for normal restored/promoted-tab construction; this does not reset the separate host bypass q.

[Destroy](../code-evidence/android/ad-blocking/excerpts/static-B05-destroy.smali.txt), `WebBrowser.E0:3798–3872`, nulls clients/download listener, clearView, destroyDrawingCache, destroy, catching Throwable. **No stopLoading or clearCache call.** `E1:3875–3915` is the separate guarded stopLoading helper. Nested children are created independently and are not shown linked into a recursive destruction tree.

**Status:** explicit create/classify/promote/dismiss/destroy/stop callers traced; protected activity teardown remains a static gap. **Runtime verification pending** for requests/scripts/workers before disposal, callback order, nested-child survival and notification races. No player/click continuity is inferred (B06).

## B07 — Interception decision tree and response meanings

## B11 — Update transactions, cancellation, recovery and lookup caches

The [staging method](../code-evidence/android/ad-blocking/excerpts/static-B11-staging.smali.txt) `fc.f:2190–2954` commits LOADING status through n9.j, inserts **20,000-host batches** via fc.e (1147–2188), activates via fc.a, then purges obsolete inactive loads via fc.b. These are separate transactions; there is **no whole-fetch/stage/activate transaction**. Partial batches can remain after failure without becoming active.

Activation `fc.a:167–416` builds LOADED/active=true, passes `l9` selector 0 → `n9.h:969–1396` into `smali/uqd.N:2345–2713`: update new load, query other active UUIDs (`f9:5929`), mark them inactive, all inside that transaction wrapper. The Room compatibility branch delegates to p5b.V/transaction executor; the connection branch uses `rg1` selector 11 → `je2` → `b2c.d`. Implementations `smali/rx8.d/g/e/f` and `vh8.d/e` are retained: rx8.g (1390–1801) invokes rollback on thrown body paths and commit/end on successful paths; rx8.e uses BEGIN or SAVEPOINT, rx8.f uses END/ROLLBACK or RELEASE/ROLLBACK TO SAVEPOINT. SQLException during rollback is attached/rethrown. This is concrete rollback code, **not evidence of crash durability, selected database journal mode, or the actual runtime driver**.

Worker `AdBlockLoadWorker.a:~695–758` returns Success normally, catches Exception (including coroutine cancellation exceptions in the JVM hierarchy) → logs/Failure; no unconditional cleanup finally changes a failed LOADING record there. fc.f has no catch/finally rollback for all prior batches. `z8` cancellation helper and `fc.h` can mark CANCELED separately. Cancelling WorkManager and writing CANCELED do not synchronously prove a running worker can no longer activate.

Recovery exists: successful `fc.b:418–730` selects statuses with `cb.a=true` (CANCELED/DISCARDED/LOADED; **not** LOADING/TRIGGERED), then `n9.i:1398–1993` queries inactive loads where `(appInstance<>current OR status IN terminalStatuses)` and deletes selected loads through e9 (default branch:73–87); the `AdBlockItem` foreign key declares ON DELETE CASCADE (`tz:8139`). Consequently inactive abandoned LOADING/TRIGGERED rows from a **different app instance** can be swept on a later successful purge; same-instance nonterminal rows are not selected solely for age. Active rows are excluded. No unconditional startup sweep, timeout reaper, startup replay-to-activate, or automatic resume of partial host batches was found. Recovery depends on a later reachable successful rebuild/purge; protected startup scheduling remains B04.

Lookup cache `fc.b` field is a ConcurrentHashMap keyed by supplied host, storing positive and negative booleans (`fc.c:732–874`, d:876–1145), with no size/TTL bound in these methods. Activation clears it **after** the transaction returns (fc:406–410), not inside the database transaction. `a9.a:43–265` coalesces pending per-host jobs in fc.d LinkedHashMap under a monitor, starts a deferred in the shared fc.c scope, waits at most **250 ms** through `yb` selector 1 (`yb.invokeSuspend:244–287` → `classes7/bdd.n0:12132–12349`, timeout-or-null), and `smali/ub` selector 0 completion callback (9023–9117) removes only the identical pending deferred. A timed-out wait returns null to a9, which returns false; the separately scoped lookup can still complete/cache afterward. Pending jobs are **not** cleared/cancelled by activation. A lookup started against old data can finish and put a stale boolean after the clear; no load-generation check guards c/d's put. This is a source-supported race possibility, not an observed stale-cache failure.

**Status:** static trace complete for visible transactions, cleanup, cancellation and caches; **runtime verification pending** for concurrent rebuild/reader races, interrupted activation, orphan sweep effectiveness and crash recovery. Protected startup/teardown means their recovery callers cannot be certified complete.
