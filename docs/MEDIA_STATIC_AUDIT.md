For the response-header loop that is actually reached, **`jd9.c` receives the wrapper's resolved URL**, rather than unconditionally the original proxy source URL. Raw register trace in `AbstractMediaProxyServlet.x:6379–6381`: `ld9.v()` → `v4`. Internally consumed redirect responses are not saved by this servlet loop; the inspected OkHttp jar is no-op and the Ktor construction installs no cookie plugin. These are static properties; no cross-host packets or cookie loss were reproduced.

## Proxy header modes and complete retry selector

`x` prepares stored headers, exact-URL cached overlay, current-cookie/fallback selection, Accept `*/*` and Accept-Encoding `identity`, then chooses its engine. Header replacement (`bo9.e`) differs from addition (`bo9.a`). `Referer` and `Origin` have dedicated branches: a nonempty stored value is used except at attempt 1; Referer otherwise tries the incoming downstream value. Generic stored-header copying excludes Referer, UA, Origin and lowercased names containing `range`. Cached headers overlay later and can reintroduce/replace those names. Therefore attempt 1's omission of a stored Referer/Origin is not a universal prohibition on forwarding either header. Cached maps are aliased by servlet `r`, not defensively copied, despite `jd9.b` making a copy for other callers.

**Correction to the earlier HTTP checkpoint:** the stored-header predicate is `range`, not `accept-encoding`. At `x:3982–3993`, every pass calls hasMoreElements, then executes `const-string v7,"range"` **before** testing whether enumeration is over. Even though the body can change v7 to `accept-encoding` at 4035, the final loop pass resets it to `range` before taking `cond_a`; it is not reassigned before the stored loop's `contains(v7)` at 4619. This establishes the register value at the consumer, rather than treating one assignment in the loop body as its exit value. The later explicit Accept-Encoding replacement still sets `identity`. The full method excerpt preserves both loops and their join.

`v:1665–1702` returns true for status 400–599 inclusive or a negative status. The common retry decision at 8716 onward also considers an exception or missing response. This is an application compatibility retry, separate from engine redirect/auth follow-ups.

## Ktor streaming: headers, backpressure and teardown

`rz5.a:157–738` allocates a 65,536-byte PipedInputStream connected to a PipedOutputStream, two AtomicReferences (metadata and first error), and a CountDownLatch. It starts a daemon `oz5` thread named `ktor-proxy-<counter>` and calls `await()` without a local wait timeout. Network HttpTimeout configuration is separate. A pre-header producer error causes the waiting caller to close input and throw mapped IO/timeout errors.

`oz5.run` selector 0 → `wc.invokeSuspend` selector 6 → `oy3.o` → `t8.invokeSuspend` selector 20 → private `t8.k:714–1005`. The callback publishes headers/status/final URL into `pz5`, **counts down the latch before copying the body**, then copies the response channel to the output pipe with a 65,536-byte buffer. This is bounded streaming with backpressure, not whole-response buffering. Normal/error `oz5` completion counts down and closes output; first error uses compareAndSet. `oy3.o` cleans the response on success or failure through `oy3.f:1977–2255`, including channel/job cleanup and awaiting the job. The channel-backed input wrapper `it0.close` selector 0 cancels its channel through `ead.h`.

The returned `qz5` retains metadata and pipe input, **not** the daemon/job or producer error reference. `qz5.close:53–71` closes that pipe input only. There is no direct wrapper-close→thread-interrupt/job-cancel link. If failure occurs after headers, the caller has already received its wrapper: the original producer throwable is not explicitly surfaced by `qz5.read`, while final output closure can yield EOF or a pipe error. Do not claim precise truncation/error/teardown outcomes without runtime instrumentation (M18). A blocked upstream read is not the same event as the next failed pipe write.

## Adaptive formats and delivery boundaries

HLS has three different implementations: validation prefix checking; URI/attribute rewriting (`uda`/`ag8`); and parsing/delivery (`no4`/`ko4` or Media3 player/export). The parser's capabilities must not be attributed to every consumer.

The extension-recognition lists in authoritative `uc7.<clinit>:21–282` include video/container suffixes `mp4,mkv,avi,3gp,m4v,webm,flv,ogv,ogg,mov,qt,wmv,asf,m4p,mpeg,mpg,mp2,mpv,3g2,m3u8,ts,vob,mpd`; audio `mp3,wav,aac,flac,m4a,oga,wma`; and separate image suffixes. These are recognition heuristics, not a codec/receiver support promise. The raw literal `qt` corrects a misleading SDK constant name in reconstructed Java. The connected save enum additionally contains UNKNOWN, which is not another demonstrated conversion strategy.

`no4` in `smali_classes2` parses master/media structures including STREAM-INF, MEDIA renditions, SESSION-KEY, BYTERANGE, MAP, discontinuity and sequence tags, live ENDLIST absence, parts/preload/rendition reports and encryption metadata. Its regex accepts NONE/AES-128/SAMPLE-AES/SAMPLE-AES-CENC/SAMPLE-AES-CTR and KEYFORMAT. It can construct DRM metadata. **Parsing those declarations does not establish playable/decryptable delivery.** The custom `ko4` path selects a main variant (`format.k`, descending comparator) and can change selection using measured throughput (`jo4`). It copies successive selected media-segment InputStreams and has live playlist polling/reload. Byte-range length/offset are passed into `ko4.e`; conventional full-segment AES/CBC/PKCS7 handling uses `se` when usable key/IV are present. The inspected custom copy path does not consume initialization/discontinuity/DRM fields `bo4.b/d/f`, nor demonstrate muxing separate audio/subtitle renditions. Missing support in this consumer is not absence from Media3.

`uda`/`ag8` resolve non-comment lines and `URI="..."` attributes, produce registered proxy destinations, conditionally supply Origin/Referer, append selected query/header hints, and can change codec text. This rewrites manifest references; it does not transcode samples. Relative resolution uses the applicable base, with URL/URI fallback and stage-specific decoding; no single pre-normalization is assumed.

DASH proxy rewrite is connected: `x` detects MIME/extension or `.mpdremote` → `vh2.b` → DOM/XPath transforms with `q3/f01/gd9` URL callbacks → generated proxy destinations. `vh2.b:393–590` handles Location/PatchLocation/BaseURL, SegmentURL media/index, Initialization sourceURL, InitializationSet, RepresentationIndex and SegmentTemplate media/initialization attributes; later branches include Period/SegmentList/InitializationSet href. This is XML/reference adaptation, not DASH segment muxing or license acquisition. Local playback separately creates DashMediaSource; MP4 export separately uses Media3 asset loaders. Manifest namespace variants, dynamic timelines, discontinuities, live windows, unsupported init layouts and license-enforced playback require runtime checks rather than a universal format-support claim.

## Dispatch, casting and subtitles

Selected candidate → `y97.u/h/x/l` → `w87` callback → `yp3` plus `d77` carrying URL, headers, MIME, page/private context. `y97.H` starts the internal-player activity/service; the external action creates an intent; remote playback passes `Application.L` → `zyc/bzc` → `Application.K` → `v67.g0` → `p4` selector 3 → `v67.e0/f0` → receiver `ca7.M/l`. See [pipeline receiver table](ANDROID_MEDIA_PIPELINE.md) and [receiver adapter index](../results/android-receiver-adapters.json). That older index lists direct implementors, not all inherited subclasses.

Direct URL and phone-hosted delivery are distinct outcomes of `Application.K`, file/content routing, format/receiver policy and proxy registration (`zfa`/`yla`). Google Cast's extended metadata path goes through `df4`/MediaInfo and receiver load callbacks. FireTV uses Amazon setMediaSource through its standard method while its extended M is a stub; several DLNA/WebOS/Netcast/AirPlay adapters likewise use the standard path when extended M is unavailable. A stub extended method does not establish that an adapter cannot cast. Network success callbacks confirm only what their implementation reports; receiver decoder behavior is still M23.

[Subtitle pipeline](ANDROID_SUBTITLE_PIPELINE.md) connects track discovery/selection → `mbb.e/gab/w92` → parser/conversion/charset → `SubtitlesServlet` and receiver dispatch. SRT, VTT, TTML/DFXP and ASS/SSA have distinct parser/writer paths. Charset detection/BOM handling and Windows-1252 fallback are explicit. ## Saving, resumption and cleanup

Create-document result → pending `n33` → local/content copy or network Room record → observation → scheduling. `z8` selector 3 uses unique `download-<id>` WorkManager work with KEEP, LINEAR ten-second backoff, and a predicate that suppresses a second ENQUEUED/RUNNING job. Its `v60.b` flag specifies backoff criteria, not expedited execution. Persisted status is distinct from WorkManager state: PAUSED/COMPLETE/FAILED/QUEUED/DOWNLOADING/WORK_SCHEDULED/TRANSFORMING. No global active-job cap follows from the notification/resource active count.

`DownloadWorker.e` accepts eligible WORK_SCHEDULED/FAILED records with URL, prepares the selected strategy and destination, and delegates transfer/export. `d` can record PAUSED on cancellation while returning worker Failure. Retriable IO results use Retry through attempt threshold 10; result mappings remain eq6 Failure / fq6 Retry / gq6 Success. The database insertion/update and scheduling are separate steps, not a transaction shared with a destination document or WorkManager database. Seven SQL builders are indexed; no atomic all-three commit exists in the traced chain. Protected application startup limits universal abandoned-record recovery claims.

**Resumption is append based:** `e:5533–5596` accepts `content://` destinations and opens the descriptor in `"wa"` mode. `c:1704–1794` uses descriptor stat size >2 to set `Range: bytes=<size>-`; `c:1909–1976` accepts the response success flag, creates FileOutputStream from that descriptor and reads Content-Length while logging Content-Range. It does not validate status 206, the returned start offset, ETag/If-Range or unchanged entity identity in that transfer body. Content-Range is not a demonstrated offset validator merely because it is read. Loop writes update byte/progress records; `yv0.k` closes stream/body/response/descriptor on normal and exceptional paths. This is a concrete integrity concern for ignored ranges, changing content and transformed/live output, not a reproduced corrupt file. SAF provider stat/append behavior is M28.

ORIGINAL (`p98`) sometimes wraps a URL in the local media proxy; direct manifest cases copy supplied headers and selected cookies, and already-local generated URLs are preserved. It means original selected resource, not necessarily a complete offline movie. TS_FROM_M3U8 (`py6`) routes through a generated endpoint into `ko4`'s assembly path. MP4_FROM_MPD/HLS (`ihb` → `rh3` selector 3) uses Media3 export. `TransformerInternal.SequenceAssetLoaderListener.shouldTranscode` makes per-track transmux/transcode decisions; codec selection and actual support depend on device/inputs. No connected screen-capture save path was found in the selected app/script call graph; unrelated SDK capture symbols are not evidence of such a product feature.

Temporary export path is `output_<timestamp>.mp4` under the app cache. The callback/continuation chain (`nv8`, `mh5`, `bh0` selector 6 → `fi0` selector 15 → `s2c.b`) reports success/error/cancel and shuts down export/watchdog work. `ihb` deletes the returned file after copying or copy error. A pre-return export failure/cancel does not reach that returned-file deletion; inspected callbacks do not establish file removal then. Do not silently promote that observation into proof of a permanent leak: app-wide maintenance/protected startup and filesystem failure are separate M30/M31 boundaries.

## Lifetime, private mode and concurrency

`uwc.e/o` disposes old `omc`/context groups and PAGE resources, assigns the new tag, resets static segment-payload suppression and may preserve candidates under history configuration. `ap0` distinguishes PAGE/TAB cleanup registrations; PAGE coroutine and TAB file resources are distinct. Provider preparation rechecks URL/context and deletes stale/cancel/error output. `InternalPlayerService.onDestroy:6408–6435` clears its running flag and calls `m`: remove notification, stop/release player, null fields, unregister receiver, release locks via `q`, cancel service coroutine job and notify the activity. This proves explicit cleanup when called, not after abrupt process death.

`jd9.a` and `yxc.q` are process-shared, URL/path keyed maps, without a private-profile dimension. `jd9.a` retains an input map reference; `jd9.b` copies it, but proxy `r` returns its alias after releasing the lock. `sg1.v` and the proxy alternate URL are static, likewise not per-tab. The direct census finds no general clear/eviction for `jd9.a`; navigation cleanup does not explicitly clear segment-path mapping. `yla.g/h` have insertion-order 5,000-entry bounds; proxy DB aging deletes entries older than two days when invoked; generated playlist cleanup marks >3-day files deleteOnExit. These are different retention policies, not a single private-session purge guarantee. Persisted DownloadItem explicitly stores `incognito`, source/page URL and headers. Do not infer that private downloads are ephemeral because browser history is private.

Context changes and single-thread scheduling reduce some stale updates, but returned aliases, overlapping jobs and shared timestamp/order rules still require runtime race checks. Protected startup/teardown and private-cookie implementation internals prevent universal isolation/recovery conclusions. No secret values were needed or accessed.
